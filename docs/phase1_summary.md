# Phase 1 经验总结 (2026-06-11)

Phase 1 产出了可运行的 Web 可视化 + Newton-Raphson 求解器。Phase 2 代码全部重写，本文档作为参考。

## 验证过、保留的思路

### 两阶段分解
- 阶段 1：2×2 Newton-Raphson，从连杆约束求解 (θ, ψ)
- 阶段 2：由 arm 姿态算出 U, T（三角闭环刚性，0 DOF）
- 分解干净、正确

### Web 前端布局
- 左：生长树导航（参数选择）
- 中：Three.js 3D 视口 + 视角按钮（+X, -X, +Y, -Y, +Z, -Z, Home）
- 右上：参数滑块面板
- 右下：β₁×β₂ 解空间网格（自动计算，可点击/拖拽）
- 轨迹追踪（T, U, Q, A 四点轨迹线）
- 布局好用，保留

### 解空间网格技术
- 70×70 β₁×β₂ 网格，邻域初始猜测（左边/上方的解做种子）
- 异步分批：每 2 行一个 setTimeout(0) tick → UI 不卡
- 颜色编码：深色 = 无解，蓝绿 (ψ≈0°) → 红 (|ψ|≥30°)
- Canvas 坐标缩放 scaleX/scaleY 正确处理 CSS 缩放

### Newton-Raphson 求解器
- 有限差分 Jacobian（eps=0.001°）简单有效
- 收敛参数：tol=1e-4, max 50 次迭代
- 发散保护：|θ|>180 或 |ψ|>180 则放弃
- 宽松接受：残差 < 0.05 也接受（处理边缘格子）

## 需要改进的问题

### 三角闭环 P-U-Q 刚性（关键发现）
- 用户最初认为 link 和 plate 可以在 U 处相对转动
- 实际上三角闭环 3 个 Y 轴旋转关节 → 0 DOF → 刚性
- 刚性是数学正确的，不是 bug
- 但 U₀ 硬编码在 Z 轴 (0,0,L_U) 导致 P-U-T 共线，视觉误导

### 生长模型过于简化
- 生长模型只有 L_U（距离），没有方向 → U 被放在 Z 轴上
- 需要更丰富的生长参数（角度或偏移）来正确描述 U 的位置
- 或者：明确接受 Z 轴放置，在文档中说明

### ψ 参数是后加的
- 最初只有 θ，ψ 是后来补充的
- 有效角度 α = α₀ + ψ, γ = γ₀ + ψ
- 参数命名不一致：alpha/alpha0, gamma/gamma0, L_cp/L_BP 散落 fallback
- 重写时：从一开始就统一命名

### 代码组织
- compute.js, explorer.js, grid.js, scene.js, ui.js, main.js — 6 个小文件互相耦合
- main.js 中大量共享状态
- 重写时：考虑更少、更内聚的模块
